# 이전 대화를 사업 맥락으로 이식하기

## 접근 범위

스킬은 지침이지 계정 전체 대화에 대한 권한이 아니다. 사용할 수 있는 것은
현재 세션에 보이는 대화, 선택해서 제공한 대화 파일, 명시한 프로젝트 자료,
호스트가 실제 제공하고 허용한 검색 결과다. 스킬 자체에는 채팅 내보내기·
다른 계정 로그인·로컬 숨김 로그 탐색·크롤링 기능이 없다.

전역 설치를 했어도 자동으로 모든 프로젝트를 합치지 않는다. 현재 프로젝트에
자료가 없다면 `.venture/venture-context.md`가 없다고 밝히고 지정한 자료로 진행한다.

## 권장 작업 공간

```text
my-business/
  .venture/
    README.md
    venture-context.md
    business-input.md
    projects/
    sources/
    evaluations/
    reports/
```

현재 세션에서 “지금까지 이야기한 사업들을 평가해줘”라고 요청하면 읽을 수 있는
대화를 사용한다. 새로운 세션에서 “지난 대화를 평가해줘”라고 했는데 자료가 없으면
대화 요약이나 파일을 요청한다. 접근 가능한 자료가 없는데 “기억한다”고 하지 않는다.

## context 모드 절차

1. 대상 프로젝트와 자료 범위를 확인한다.
2. 고객/문제/상품/가격/채널/운영/지표/제약을 추출한다.
3. **사용자가 채택한 결정**, **AI가 제시했을 뿐인 제안**, **실행 확인**을 분리한다.
4. 동일한 사업의 이름 변경은 근거가 있을 때 묶고, 별개 사업을 임의로 합치지 않는다.
5. 출처가 상충하면 날짜와 주장을 함께 보존한다.
6. 이전 AI 점수는 “이전 판정”으로만 기록하고 새 사실의 근거로 쓰지 않는다.
7. 맥락 템플릿을 채운 초안을 출력한다. 저장 요청이 있으면 실제 파일로 남긴다.

외부 앱과 공유하는 것을 원하지 않는 민감 정보는 넣지 않는다. 별도의 사용자 지시
없이 투자자 이름, 개인 건강, 소송, 자격증명 등 무관한 개인정보를 추출하지 않는다.

## 저장 방식

맥락 처리의 기본은 읽기와 초안 출력이다. 일반 평가 모드의 HTML 보고서 생성과는
구분한다. HTML 작성이 기존 맥락 갱신이나 다른 프로젝트 자료 수집을 허용하지 않는다. 사용자가 “저장”, “맥락 갱신”을 요청하면 저장이
허용된 작업 경로만 사용한다. 기존 맥락이 있으면 먼저 읽고 삭제·충돌 여부를 확인한다.
수정 전에 변경점을 설명하고, 큰 삭제/상충 해결은 사용자 확인을 받는다.
새로운 평가 파일은 기존 것을 보존하고, 변경이력에는 일자·근거·요약만 적는다.

스킬 설치 폴더는 버전업 대상이므로 사업 데이터를 넣지 않는다. Claude와 Codex가
같은 로컬 작업 폴더를 열면 이 파일을 함께 읽을 수 있지만, 클라우드 세션·별도 기기·
서로 다른 작업 폴더에 자동 복사되지는 않는다.

## 이식용 요청 예시

기존 대화에서:

> 지금까지 이 대화에서 논의한 사업 중 내가 실제로 채택한 결정과 네가 제안한
> 아이디어를 구별해서 venture-context.md 초안으로 정리해줘. 매출·사용자·
> 리텐션 등 확인되지 않은 수치는 미확인으로 남겨줘.

새 환경에서:

> venture-evaluator를 사용해 첨부한 venture-context.md만으로 portfolio 평가를
> 해줘. 계획과 실제 성과를 나누고, 최신 경쟁 정보가 필요하면 별도로 확인해줘.

## 자동 수집을 하지 않는 이유

다른 프로젝트 비밀의 혼입, 과거 가설을 현재 사실로 오해하는 문제, 접근 권한
혼동을 막기 위해 선택된 자료만 읽는다. 파일 저장·컨텍스트 로딩은 모델 학습이나
파인튜닝이 아니며 기억의 완전성도 보장하지 않는다.
