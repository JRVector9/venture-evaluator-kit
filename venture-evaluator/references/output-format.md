# 출력 계약 · Report Edition 1.1

**기본 전달 형식은 HTML 보고서 + JSON이다.** 아래 내용은 보고서에 들어가는
분석 내용의 계약이며, 채팅 Markdown만으로 끝내라는 지시가 아니다.
실제 파일 생성은 `html-report.md`를 따른다. `md` / `no-save`일 때만 아래를
채팅 내 Markdown 출력으로 사용한다.

HTML에서는 표지가 앞에 오고, 경영진 요약 바로 다음에 GSR+ 비교표를 배치한다.

## 기본 보고서

맨 위에 아래 내용을 짧게 적는다.

> 평가일: [현재 날짜] · 관점: Founder / Investor · 단계: 아이디어 / MVP / 운영
> 입력: [읽은 파일·대화·지표] · 외부 확인: [수행 범위 또는 미실시]
> 이 표는 GSR-inspired 자체 분석이며 현재 실적과 조건부 잠재력을 구분한다.

### 1. 비교표

| 서비스 | Significant | Scalable | Sustainable | 고빈도 | 네트워크 효과 | GSR+ 잠재력 |
|---|---|---|---|---|---|---|
| [사업] | [기호] | [기호] | [현재→조건부] | [기호] | [기호] | [조건부 라벨] |

표 아래에 `◎ 강함 · ○ 유리하나 미완성 · △ 약점 · × 구조적 부적합 · ? 근거 부족`
한 줄을 둔다. 화살표 오른쪽은 달성한 점수가 아니라 조건부 가설이라고 쓴다.
모든 미래 기호를 근거 없이 `◎`로 통일하지 않는다.

### 2. 판정 이유

각 사업당 다음 네 문장/단락을 유지한다. 사용자가 상세 분석을 요청하지 않았으면
포트폴리오 상위 검토 대상 3개는 상세하게, 나머지도 최소한 근거 한 문장을 쓴다.

**강한 이유:** [핵심 구조 + E1 등 근거]
**핵심 위험:** [무료 번들/커스텀/결제/유통 등 가장 큰 반대 근거]
**바꾸면 달라지는 점:** [작은 구조 변화와 화살표 조건]
**근거 신뢰도:** [높음/중간/낮음 + 모르는 것]

### 3. 최소 검증

| 가설 | 대상·기간 | 행동/실험 | 성공 기준 | 중단·재설계 기준 | 비용과 가정 |
|---|---|---|---|---|---|
| [핵심 가설] | [첫 고객, 관측 기간] | [최소 실험] | [정의·분모 포함] | [반증 조건] | [가정 명시] |

새 숫자는 `제안 목표`로 명시한다. 단순 인터뷰 의향과 실제 결제를 구별한다.
표본이 작거나 불완전하면 PMF/전면 확장의 증거로 과대 해석하지 않는다.

### 4. 결론과 미확인

`지금 검증할 것 / 나중에 할 것 / 하지 않을 것`을 짧은 문장으로 정리한다.
결론을 바꿀 질문은 최대 3개다. 모르는 항목을 전부 물어보고 작업을 멈추지 않는다.

## Deep 모드 추가

12항목별 `현재 판정 / 근거 / 개선 조건 / 신뢰도` 표, 근거 원장,
30/60/90일 검증 계획, 단계별 예산, 전제가 깨지는 경우를 덧붙인다.
가격·비용·시장 가정은 읽은 실제 자료와 분리한다.

## Portfolio 모드

같은 자료량을 읽었다고 가장하지 않는다. 사업별 단계와 출처 범위를 적는다.
원하면 실행 우선순위를 제시하되 `VC 적합성`, `현금화 속도`, `보유 자원 적합성`
중 어느 목적을 기준으로 정했는지 밝힌다. 필수 시장/결제/권한이 미상이면
단정적인 전체 1위를 만들지 않는다. 많은 문서를 가진 사업을 자동 우대하지 않는다.

## Update 모드

이전 보고서와 새 자료를 각각 실제로 읽는다.

| 사업/항목 | 이전 | 이번 | 바뀐 근거 | 남은 불확실성 |
|---|---|---|---|---|

루브릭 버전이나 평가 목적이 바뀌었으면 실적 개선과 구별한다.
새 근거가 없으면 그 사실을 쓰고 점수를 억지로 바꾸지 않는다.

## Context 모드

평가표를 강제로 출력하지 않는다. `assets/venture-context.template.md` 형식으로
사업 사실·사용자 결정·미채택 아이디어·미확인·출처를 정리한다.
사용자가 요청한 사업 범위 밖의 개인 이력은 넣지 않는다.

## 파일 저장

HTML 평가에서는 신규 `.html`과 재생성용 `.json`을 기본으로 만든다.
`context` 갱신과 Markdown 이력 저장은 명시 요청에 따른다. 파일을 실제 만든 후 경로를 제공한다.
날짜·시각이 겹치면 새 이름을 사용한다.

```text
.venture/
  venture-context.md
  projects/
    <project-slug>.md
  reports/
    YYYY-MM-DD-HHMMSS-<project-or-portfolio>.html
    YYYY-MM-DD-HHMMSS-<project-or-portfolio>.json
  evaluations/
    YYYY-MM-DD-HHMMSS-<project-or-portfolio>.md  # 별도 요청 시
  sources/
    <user-selected-files>
```

호스트가 파일을 만들 수 없으면 보고서 내용을 출력한다. 그 환경에서 읽을 수 없는
로컬 경로를 링크로 주거나 다른 호스트에 자동 동기화된다고 하지 않는다.
