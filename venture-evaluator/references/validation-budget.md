# 최소 검증과 예산

## 검증 순서

먼저 사업을 막는 제약을 조사한다. 고객 데이터 접근권, API 승인, 자격·안전,
조달 계약, 민감 데이터 처리 등이 막혀 있으면 제품을 먼저 만들지 않는다.

이후 핵심 가설 한 개를 선택한다. 기존 문제의 빈도·비용, 결제, 반복 사용,
표준 온보딩, 지원 원가, 네트워크 교차가치 중 무엇이 결론을 뒤집는지 적는다.
인터뷰만으로 제품시장적합성(PMF)을 선언하지 않는다.

검증은 문서/스프레드시트/수동 보조/단일 기능 프로토타입으로 시작할 수 있다.
수동으로 대신한 업무가 많으면 그것을 AI 자동화 성과로 표시하지 않는다.
고객 안전·계약·금전 관련 작업은 검토/승인 단계를 포함한다.

## 가설 카드

- 대상과 결제자: [어떤 첫 고객, 접근 경로]
- 기존 기준: [현재 완료시간/비용/실패율, 자료가 없으면 먼저 측정]
- 테스트: [기능 하나 또는 수동 실험]
- 기간/표본: [가정임을 표시]
- 성공 기준: [행동·분모·기간이 있는 측정값]
- 중단 기준: [가설이 깨지는 관측]
- 품질 방어선: [오답·환불·이탈·수작업 개입 상한]
- 다음 투자 조건: [무엇을 확인한 뒤 얼마나 더 쓰는가]

예시 목표 숫자는 산업 공통 합격선이 아니다. 소수 표본 결과는 탐색적 증거로 쓴다.

## 가치와 자동화 지표

`안전하게 완료되어 고객이 가치를 인정한 업무 / 활성 유료 고객 / 주`를 후보로
쓸 수 있다. 분류·알림·단순 조회를 여러 액션으로 쪼개 지표를 부풀리지 않는다.
반드시 정확성, 수정/재작업률, 수동 운영시간, 실제 재결제 등과 함께 본다.

절약 시간은 `동일 업무의 기존 중앙값 - 도입 후 중앙값`에 적절한 건수를 곱하되
검수·오류수정·온보딩 시간을 뺀다. 기존 시간이 없으면 추정치라고 명시한다.
네트워크 가치는 사용자 수 대신 매칭 성사율, 처리 시간, 검색 적합성, 납기,
기여이익 등 기존 참가자에게 돌아가는 효과로 검증한다.

## 예산 작성 규칙

**범위:** 통화, 기간, 고객/작업량, 포함 기능, 세금 포함 여부, 창업자 노동을 밝힌다.
근거 없는 시장 견적을 사실처럼 쓰지 않는다. 견적이 없으면 “계획 가정”이다.

| 구분 | 항목 | 수량 | 단가 | 횟수/개월 | 소계 | 근거/가정 |
|---|---|---:|---:|---:|---:|---|
| 일회성 | 개발/디자인/초기 점검 | [ ] | [ ] | [ ] | [계산] | [ ] |
| 반복 | 호스팅/API/도구 | [ ] | [ ] | [ ] | [계산] | [ ] |
| 변동 | 고객 지원/검수/작업량 | [ ] | [ ] | [ ] | [계산] | [ ] |
| 검증 | 고객 모집/실험 | [ ] | [ ] | [ ] | [계산] | [ ] |
| 예비비 | [적용 기준] | — | — | — | [계산] | [비율 가정] |

`소계 = 수량 × 단가 × 반복 횟수`, `총계 = 모든 소계의 합`이다.
예비비가 무엇을 기준으로 계산됐는지와 이미 포함된 항목을 명확히 한다.
가능하면 실행 환경의 계산 도구로 합계를 검산한다.

창업자의 무급 노동을 0원짜리 자원으로 숨기지 않는다. **현금 지출**과
**창업자 투입시간/기회비용**을 별도 표시한다. 신규 장비, 법무, 보험, 데이터
권리 비용이 필요한 업종은 빠뜨리지 않는다. 임의 환율은 쓰지 않는다.

인건비 견적은 사용자 제공 단가가 우선이고, 공개 시장 단가를 쓰면 출처와 시점을
붙인다. AI API 비용도 최신 공개 요금 또는 제공된 계약 단가로 계산한다.
요금 조회를 못 하면 단가 범위를 가정하고 민감도 분석으로 보여준다.

## 시나리오

보수/기준/확장 시나리오에서 고객 수, 사용량, 수작업, 지원비를 바꿔본다.
`월 기여이익 = 매출 - 결제/플랫폼 수수료 - 추론/호스팅 변동비 - 직접 지원/검수비`.
다른 원가 정의를 쓰면 그 기준을 적는다. SaaS의 변동원가를 AI 토큰으로만 제한하지 않는다.
`손익분기 유료 고객 수 = 월 고정비 / 고객당 양(+)의 기여이익`.
음수 기여이익이면 고객을 늘려 해결된다고 하지 않는다.

이탈률이 안정적으로 관측되지 않은 초기에 LTV를 기계적으로 계산하지 않는다.
대신 실제 유료 코호트의 누적 기여이익, CAC와 회수 기간의 관측 한계를 쓴다.

## 투자 게이트

0단계: 접근권·기존 수요 확인 → 비용 상한과 중단 시점 설정.
1단계: 작은 실험에서 유료 가치와 반복 사용 확인 → 제한적 제품 개발.
2단계: 원가·품질·온보딩 재현 확인 → 유통 확대.
3단계: 교차가치/밀도 확인 → 필요한 경우에만 네트워크 확장.

무조건 SaaS→Marketplace→API로 바꾸지 않는다. 네트워크가 필요 없다면
표준화된 고마진 업무 소프트웨어로 남는 경로도 같은 무게로 검토한다.
